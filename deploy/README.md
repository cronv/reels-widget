# Размещение

## Что куда ставится

Виджет состоит из двух частей, и у них разные требования.

| Часть | Что это | Куда ставится |
|---|---|---|
| Кнопка на сайте | один тег `<script>` | на сайт, как есть — файлы загружать не нужно |
| Сервис рендера | контейнер: Node + Chromium + ffmpeg | **VPS с Docker** |

**Почему нужен VPS, а не обычный хостинг.** Рендер собирает видео так:
headless Chromium открывает сцену, перематывается покадрово и отдаёт кадры
в ffmpeg. Нужны право запускать процессы, ~400 МБ памяти под браузер,
рабочий `/dev/shm` и свой бинарь ffmpeg. Классический виртуальный хостинг —
у любого провайдера, не только у reg.ru — исполняет код сайта в песочнице,
а не произвольные бинарники; даже на тарифах с поддержкой Node.js поставить
туда Chromium не выйдет.

Сайт при этом никуда не переезжает: он получает одну строку в шаблоне,
а сервис живёт отдельно.

**Ресурсы VPS.** Минимум 2 ГБ RAM и 2 ядра, диска хватит 10 ГБ.

Память считается перемножением: `RENDER_CONCURRENCY × RENDER_WORKERS`
процессов Chromium по ~400 МБ каждый, плюс ffmpeg.

| Настройка | Что делает | По умолчанию |
|---|---|---|
| `RENDER_CONCURRENCY` | сколько роликов собирается одновременно | 1 |
| `RENDER_WORKERS` | сколько процессов снимают кадры одного ролика | 2 (не больше числа ядер) |

Значения по умолчанию дают те же ~800 МБ, что и раньше, но расходуют их
иначе: один ролик за раз, зато вдвое быстрее. Это осознанный выбор в
пользу ожидания у экрана. На двух ядрах два ролика сразу всё равно не
шли параллельно — они делили те же ядра и каждый ждал вдвое дольше.

Поднимать `RENDER_CONCURRENCY` стоит, только если роликами пользуются
несколько человек одновременно и памяти на сервере с запасом.

## Установка

Нужен Docker с плагином compose (`docker compose version`). На чистой
Ubuntu/Debian: `curl -fsSL https://get.docker.com | sh`.

```bash
mkdir -p /opt/reels-widget && cd /opt/reels-widget
tar -xzf reels-widget-*.tar.gz --strip-components=1

cp deploy/.env.production.example .env
nano .env                       # заполнить адреса, см. ниже

docker compose -f deploy/docker-compose.yml up -d --build
```

Сборка занимает несколько минут: ставятся Chromium, ffmpeg и шрифты.
Готовый образ — примерно 500 МБ, из них около 300 МБ приходится на
Chromium; меньше для браузерного рендера не выходит.

Если в проекте нет `package-lock.json`, образ соберётся, но версии
зависимостей могут разъехаться между сборками. Зафиксируйте их один раз:
выполните `npm install` на машине разработчика и положите получившийся
`package-lock.json` в репозиторий — дальше сборка станет воспроизводимой.

Сразу после запуска — проверка окружения:

```bash
docker compose -f deploy/docker-compose.yml exec reels npm run verify
```

Она отвечает на вопрос «почему не собираются ролики» до того, как он
возникнет: показывает версию браузера, наличие ffmpeg и — главное — есть ли
в образе шрифты с кириллицей. Без них весь русский текст в кадре станет
квадратами, и заметить это можно только глазами в готовом файле.

Полная проверка, с настоящим видео (около двух минут):

```bash
docker compose -f deploy/docker-compose.yml exec reels npm run smoke
```

### Что заполнить в `.env`

```ini
# доступ — без этого в продакшене сервер не стартует
ACCESS_PASSWORD=<пароль для менеджеров>
AUTH_SECRET=<openssl rand -base64 32>

PUBLIC_URL=https://reels.вашдомен.ru      # адрес, по которому сервис виден снаружи
ALLOWED_ORIGINS=https://вашсайт.ru        # кто может встраивать виджет
SCRAPE_ALLOWED_HOSTS=вашсайт.ru           # какие домены можно разбирать по ссылке
SCRAPE_TRUSTED_HOSTS=вашсайт.ru           # если robots.txt закрывает свой же сайт
```

Домен самого сервиса в `ALLOWED_ORIGINS` вписывать не нужно — он разрешён
всегда, иначе виджет не смог бы обратиться к собственному API. «Свой»
адрес определяется по тому, по какому имени к сервису пришли, а не по
`PUBLIC_URL`: при незаполненной настройке сервис раньше отказывал
собственной странице и писал «этому домену не разрешено».

**Поддомены.** Если у каждого объекта свой поддомен, перечислять их по
одному необязательно — работает звёздочка:

```ini
ALLOWED_ORIGINS=https://вашсайт.ru,https://*.вашсайт.ru
```

Звёздочка заменяет метки слева и не покрывает сам домен, поэтому он
указан отдельно. Правило читается буквально: `*.вашсайт.ru` не пропустит
ни `вашсайт.ru`, ни `вашсайт.ru.чужой-домен.ru`.

Проверить, кого сервис пускает, можно не угадывая:

```bash
curl -s 'https://reels.вашдомен.ru/api/embed/check?origin=https://вашсайт.ru'
```

В ответе `allowed` — решение по этому домену, `allowedOrigins` — список,
который сервис видит сейчас. Этот адрес открыт для любого домена
намеренно: он нужен именно тогда, когда всё остальное закрыто.

## Доступ

Сервис виден по публичному адресу, а один рендер занимает ядро на минуту —
без защиты его API становится чужим бесплатным видеосервисом. Поэтому
закрыты все эндпоинты, которые тратят ресурсы:

| Открыто | Требует входа |
|---|---|
| `/health`, `/api/scenarios`, `/api/auth/status` | `/api/extract/*` |
| `/loader.js` и статика виджета | `/api/timeline*`, `/api/render`, `/api/jobs*` |

Менеджер один раз вводит `ACCESS_PASSWORD` в виджете, сервер отдаёт
подписанный токен на `SESSION_TTL_HOURS` часов. Базы пользователей нет:
проверка токена — это один HMAC. Сменить пароль — поменять
`ACCESS_PASSWORD` и перезапустить; разлогинить всех разом — заодно
поменять `AUTH_SECRET`.

`loader.js` остаётся открытым намеренно: иначе у всех посетителей сайта
в консоли появятся ошибки. Кнопка видна всем, но за ней экран входа.

Поверх входа работают лимиты на одного клиента: `LIMIT_RENDER_PER_HOUR`,
`LIMIT_EXTRACT_PER_HOUR` и `LIMIT_LOGIN_PER_15MIN` — последний не даёт
подбирать пароль. Адрес клиента берётся из `X-Forwarded-For`, когда
`TRUST_PROXY=true`; если сервис смотрит в интернет напрямую, поставьте
`false`, иначе заголовок подделают и лимит обойдут.

## Домен и HTTPS

Контейнер слушает только `127.0.0.1:4000`. Наружу его выставляет nginx
на хосте — он же держит сертификат.

```bash
apt install -y nginx certbot python3-certbot-nginx
cp deploy/nginx.conf.example /etc/nginx/sites-available/reels-widget
# поправьте server_name внутри
ln -s /etc/nginx/sites-available/reels-widget /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
certbot --nginx -d reels.вашдомен.ru
```

HTTPS обязателен: сайт работает по https, и браузер не пустит со страницы
запросы и iframe по http.

Проверка: `curl https://reels.вашдомен.ru/health` → `{"ok":true…}`.

## Кнопка на сайте

Одна строка перед `</body>` в шаблоне:

```html
<script src="https://reels.вашдомен.ru/loader.js" data-reels-widget></script>
```

Кнопка появится слева внизу. По клику откроется окно, адрес текущей страницы
подставится сам и разбор запустится сразу.

Если сайт на CMS и общего шаблона нет, тег добавляется в настройках темы
в поле для кода перед закрывающим `body`.

### Настройки кнопки

```html
<script src="https://reels.вашдомен.ru/loader.js"
        data-reels-widget
        data-position="right"
        data-accent="#1B75BB"
        data-label="Сделать рилс"
        data-hide-on="/cart,/personal"></script>
```

| Атрибут | Что делает |
|---|---|
| `data-position` | `left` (по умолчанию) или `right` |
| `data-offset` | отступ от края в пикселях |
| `data-accent` | цвет кнопки |
| `data-label` | подпись; на узких экранах скрывается |
| `data-page` | какой адрес подставить вместо текущего |
| `data-autoparse="false"` | не разбирать страницу сразу при открытии |
| `data-hide-on` | пути, на которых кнопку показывать не надо |
| `data-api` | адрес сервиса, если `loader.js` отдаётся с другого домена |

Для сайтов, которые меняют адрес без перезагрузки, есть
`window.ReelsWidget.setPage('https://…')`, а также `.open()`, `.close()`
и `.toggle()`.

### Кнопка только для сотрудников

Виджет ходит по вашим страницам и тратит ресурсы сервера, поэтому на
публичном сайте показывать его всем обычно не нужно. Самое простое —
выводить тег только авторизованным менеджерам средствами CMS. Если такой
возможности нет, оставьте `data-hide-on` для публичных разделов и закройте
`/api/` по IP в nginx (пример есть в `nginx.conf.example`).

## Шрифты

В образ ставится Noto Sans — кириллица будет в любом случае. Но кадр
нарисован под Inter, и без него ролики с сервера и с машины разработчика
перестанут совпадать: вёрстка не сломается (блоки потоковые), а рисунок
букв будет другим.

Чтобы совпадали, положите файлы Inter в `deploy/fonts/` до сборки образа —
подробности в `deploy/fonts/README.md`.

## Обслуживание

```bash
# логи
docker compose -f deploy/docker-compose.yml logs -f --tail=100

# перезапуск
docker compose -f deploy/docker-compose.yml restart

# обновление: распаковать новый архив поверх и пересобрать
tar -xzf /tmp/reels-widget-новая.tar.gz --strip-components=1
docker compose -f deploy/docker-compose.yml up -d --build

# разобрать страницу без рендера, чтобы понять, парсер виноват или нет
docker compose -f deploy/docker-compose.yml exec reels \
  npm run parse -- examples/feed.sample.xml https://вашсайт.ru/объект

# проверить встраивание и скачивание на отдельном тестовом домене
docker compose -f deploy/docker-compose.yml exec reels npm run embed-check
docker compose -f deploy/docker-compose.yml exec reels npm run download-check
```

Готовые ролики лежат в томе `reels-widget_reels-output` и переживают
пересборку образа. Старые удаляются автоматически — потолок задаёт
`RENDER_KEEP_FILES`.

## Если что-то не так

| Симптом | Куда смотреть |
|---|---|
| Кнопка не появилась | консоль браузера: загрузился ли `loader.js`, нет ли ошибки CORS |
| Окно открылось пустым | через 6 секунд виджет сам напишет причину; проверить вручную — `curl '<адрес>/api/embed/check?origin=https://вашсайт.ru'` |
| «robots.txt запрещает» | добавьте свой домен в `SCRAPE_TRUSTED_HOSTS` |
| «Нужен вход» | не задан или забыт `ACCESS_PASSWORD`; пароль вводится в виджете |
| Вход слетает после перезапуска | не задан `AUTH_SECRET` |
| «Слишком много рендеров» | лимит `LIMIT_RENDER_PER_HOUR`, поднимите в `.env` |
| Русский текст квадратами | `npm run verify` в контейнере — нет шрифта с кириллицей |
| Рендер падает | `docker compose … logs`; чаще всего не хватает памяти, поднимите `mem_limit` или снизьте `RENDER_CONCURRENCY` |
| Контейнер перезапускается | `docker inspect reels-widget --format '{{.State.OOMKilled}}'`; `true` — упёрлись в память |
| Кадры пустые | картинки объекта недоступны снаружи или закрыт хотлинк по Referer |
| Кнопка «Экспортировать» навсегда осталась в «Ставлю в очередь…» | опрос задачи не доходит до сервиса. Проверяется командой `npm run download-check` — она проходит весь путь от пароля до сохранённого файла |
| Не скачивается готовый ролик | проверьте `curl -sI <адрес>/files/<имя>.mp4` — должен быть код 200. Ссылка на файл строится от адреса виджета, так что незаполненный `PUBLIC_URL` на это больше не влияет |
| В превью дёргается картинка | превью рисует дробные кадры и идёт плавно на 60 и 120 Гц; если рывки остались, смотрите загрузку процессора на устройстве — сам MP4 это не затрагивает |

## Без Docker

Если контейнеры недоступны, остаётся установка на сам сервер:
`bash deploy/install.sh` ставит Node, ffmpeg, Chromium и системные
библиотеки, а `deploy/reels-widget.service` запускает службу через systemd.
Путь рабочий, но держать его в актуальном состоянии сложнее — набор
системных библиотек для Chromium меняется от релиза к релизу дистрибутива.
Docker здесь предпочтительнее именно поэтому.
