# Что чинить на reels.exmaple.ru

Два сбоя с разными причинами.

---

## 1. Пустое окно при встройке в сайт

**Причина — ошибка в моём примере конфига nginx.** Там стояла строка

```nginx
add_header Content-Security-Policy "frame-ancestors 'self' https://example.ru" always;
```

Домен `example.ru` остался из шаблона. Браузер читает это как «встраивать
разрешено только сайту example.ru» и блокирует iframe — молча, без ошибки
на странице. Отсюда белое окно.

**Что сделать:**

1. Обновить файлы из нового архива (в нём заголовок формирует уже сам
   сервис, из `ALLOWED_ORIGINS` — одно место вместо двух).
2. В конфиге nginx на сервере **удалить строку с `Content-Security-Policy`**:

   ```bash
   nano /etc/nginx/sites-available/reels-widget   # убрать строку add_header Content-Security-Policy
   nginx -t && systemctl reload nginx
   ```

   Если оставить её вместе с новой, браузер применит оба заголовка
   и возьмёт пересечение — блокировка сохранится.

3. Убедиться, что в `.env` перечислены сайты, где стоит кнопка:

   ```ini
   ALLOWED_ORIGINS=https://zhk-zilart.domain.ru,https://zhk-kosmos.domain.ru
   ```

   Домены пишутся со схемой `https://` и без завершающего слэша.

Проверить, что заголовок стал правильным:

```bash
curl -sI https://reels.exmaple.ru/embed/widget.html | grep -i content-security
```

Ожидается перечисление ваших доменов. Если там `example.ru` — nginx ещё
отдаёт старый заголовок.

Теперь, если домен всё же не разрешён, окно не будет пустым: в нём
появится красная плашка с точным текстом, какой домен добавить.

## 2. robots.txt по-прежнему блокирует

Логику я проверил на стенде: с `SCRAPE_TRUSTED_HOSTS` страница с
запрещающим `robots.txt` разбирается, без него — нет. Значит переменная
на сервере не применилась.

Три обычные причины, по порядку проверки.

**а) Строки нет в `.env` или файл не тот.** Compose читает `/opt/reels-widget/.env`:

```bash
cd /opt/reels-widget
grep SCRAPE_TRUSTED .env
```

Должно быть `SCRAPE_TRUSTED_HOSTS=domain.ru` — без `https://`,
без слэша, только домен. Поддомены покрываются автоматически, перечислять
каждый `zhk-*` не нужно.

**б) Контейнер не перечитал `.env`.** `restart` этого не делает — нужен `up -d`:

```bash
docker compose -f deploy/docker-compose.yml up -d
```

**в) Проверить, что видит сам контейнер:**

```bash
docker compose -f deploy/docker-compose.yml exec reels printenv | grep SCRAPE
```

После обновления в логе запуска печатаются действующие списки:

```bash
docker compose -f deploy/docker-compose.yml logs --tail=20
```

Там должна быть строка:

```
robots.txt не проверяется для: domain.ru
```

Если вместо домена `— пусто`, значит `.env` не подхватился — смотрите
пункты «а» и «б».

Заодно исправлено: раньше этот отказ отдавался как код 500 и попадал
в лог как внутренняя ошибка сервера. Теперь это 422 — ожидаемый ответ,
а не сбой.

## Порядок действий целиком

```bash
cd /opt/reels-widget
tar -xzf ~/reels-widget-20261028.tar.gz --strip-components=1

nano .env     # ALLOWED_ORIGINS и SCRAPE_TRUSTED_HOSTS
nano /etc/nginx/sites-available/reels-widget   # убрать add_header Content-Security-Policy
nginx -t && systemctl reload nginx

docker compose -f deploy/docker-compose.yml up -d --build
docker compose -f deploy/docker-compose.yml logs --tail=20
```

Проверка:

```bash
curl -sI https://reels.exmaple.ru/embed/widget.html | grep -i content-security
curl -s https://reels.exmaple.ru/health
```
