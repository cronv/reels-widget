# Настройка под reels.example.ru

Готовые значения для вашей установки. Выполняется на сервере, где
запущен контейнер.

## 1. Заполнить `.env`

```bash
cd /opt/reels-widget
nano .env
```

```ini
# ── доступ ──────────────────────────────────────────────────────────────
ACCESS_PASSWORD=<придумайте пароль для менеджеров>
AUTH_SECRET=<вывод команды: openssl rand -base64 32>
SESSION_TTL_HOURS=12

LIMIT_RENDER_PER_HOUR=30
LIMIT_EXTRACT_PER_HOUR=120
LIMIT_LOGIN_PER_15MIN=10
TRUST_PROXY=true

# ── адреса ──────────────────────────────────────────────────────────────
PUBLIC_URL=https://reels.example.ru

# Домены сайтов, куда встроена кнопка. Домен самого сервиса писать не
# нужно — он разрешён всегда.
#
# Звёздочка покрывает все поддомены, то есть любой новый ЖК заработает
# без правки этой строки. Сам домен она НЕ покрывает — поэтому он
# указан отдельно первым.
ALLOWED_ORIGINS=https://domain.ru,https://*.domain.ru

# Какие домены разрешено разбирать по ссылке.
# Поддомена здесь достаточно одного: правило покрывает и сам домен,
# и все его поддомены, то есть любой zhk-*.domain.ru.
SCRAPE_ALLOWED_HOSTS=domain.ru

# Из-за этой строки перестанет появляться сообщение про robots.txt.
SCRAPE_TRUSTED_HOSTS=domain.ru

SCRAPE_RESPECT_ROBOTS=true
SCRAPE_ALLOW_PRIVATE=false
RENDER_CONCURRENCY=2
```

Секрет сгенерировать:

```bash
openssl rand -base64 32
```

## 2. Применить

```bash
docker compose -f deploy/docker-compose.yml up -d
docker compose -f deploy/docker-compose.yml logs --tail=20
```

В логе должно быть `доступ: по паролю, сессия 12 ч` и не должно быть
предупреждений про `ALLOWED_ORIGINS` и `SCRAPE_ALLOWED_HOSTS`.

## 3. Проверить

```bash
# без токена дорогие эндпоинты закрыты → ожидается 401
curl -s -o /dev/null -w '%{http_code}\n' -X POST https://reels.example.ru/api/render \
  -H 'content-type: application/json' -d '{}'

# health остаётся открытым → 200
curl -s https://reels.example.ru/health

# пустит ли сервис виджет на конкретный домен → ожидается "allowed":true
curl -s 'https://reels.example.ru/api/embed/check?origin=https://zhk-kosmos.domain.ru'
```

Последняя команда отвечает ровно на тот вопрос, из-за которого окно
виджета открывается пустым. Если в ответе `"allowed":false`, в
`allowedOrigins` видно, что сервис считает разрешённым сейчас, —
сравните с доменом, на котором стоит кнопка.

Затем откройте любую страницу ЖК с кнопкой: появится экран входа,
после пароля страница разберётся сама.

---

## Почему было сообщение про robots.txt

На `zhk-zilart.domain.ru` файл `robots.txt` запрещает
автоматическую загрузку. Виджет это проверяет и отказывается читать
страницу — поведение правильное, менять его по умолчанию не стоит:
на чужих сайтах запрет нужно уважать.

Ваш случай другой: сайт ваш, и согласие владельца очевидно. Для этого
и есть `SCRAPE_TRUSTED_HOSTS` — список собственных доменов, на которые
проверка не распространяется. Проверка для всех остальных сайтов
продолжает работать.

Если доступ к `robots.txt` на сайте есть, лучше поправить его там:
скорее всего, запрет остался с этапа разработки и мешает не только
виджету, но и поисковым системам.

## Что теперь закрыто паролем

| Открыто без входа | Требует входа |
|---|---|
| `/health` | `/api/extract/*` — разбор фида, ссылки, формы |
| `/api/scenarios` | `/api/timeline`, `/api/timeline/available` |
| `/api/auth/status` | `/api/render`, `/api/jobs*` |
| `/loader.js`, статика виджета | |

`loader.js` остаётся открытым намеренно: иначе на страницах сайта
появятся ошибки в консоли у всех посетителей. Кнопку видно всем, но
при нажатии открывается экран входа.

Пароль один на всех менеджеров. Чтобы его сменить, поменяйте
`ACCESS_PASSWORD` и перезапустите контейнер; чтобы разом разлогинить
всех — заодно поменяйте `AUTH_SECRET`.

## Если нужно совсем спрятать кнопку от посетителей

Выводите тег `<script>` только авторизованным менеджерам средствами CMS,
либо ограничьте `/api/` по IP офиса в nginx — заготовка есть
в `deploy/nginx.conf.example`.
