# Виджет рилсов по новостройкам

Встраиваемый виджет: берёт данные о ЖК и лоте из выгрузки, со страницы объекта
или из формы и собирает вертикальные ролики 1080×1920 на 10 и 15 секунд —
по одному из четырёх сценариев.

```
фид / ссылка / форма  →  карточка объекта  →  сценарий  →  таймлайн (JSON)
                                                              │
                                              ┌───────────────┴───────────────┐
                                     превью в браузере              headless Chromium
                                     (тот же код сцены)             покадрово → ffmpeg
                                                                              │
                                                                         MP4 + обложка
```

Главное архитектурное решение: **превью и экспорт — это один и тот же код**.
Сцена (`packages/stage`) детерминирована, в ней нет ни одной CSS-анимации и ни
одного обращения к часам: всё состояние — чистая функция от номера кадра.
Поэтому `seek(n)` на сервере даёт ровно ту картинку, которую менеджер видел
в предпросмотре, и «в превью было не так» здесь структурно невозможно.

---

## Быстрый старт

```bash
npm install
npx playwright install chromium   # браузер для рендера
npm run build
npm start
```

Виджет открывается по `http://localhost:4000` и по
`http://localhost:4000/embed/widget.html` — это один и тот же интерфейс.

Чтобы проверить разбор на сохранённой странице, не выходя наружу, поднимите
сервер с `SCRAPE_ALLOW_PRIVATE=true` и дайте во вкладке «Ссылка» адрес вида
`http://localhost:4000/examples/fixtures/zhk.html`. В проде этот флаг
включать нельзя: он открывает серверу путь во внутреннюю сеть.

Сквозная
самопроверка (разбирает пример фида, рендерит все четыре ролика и сверяет
параметры файлов через `ffprobe`):

```bash
npm run smoke
```

Нужен установленный **ffmpeg** (`ffmpeg -version`) и **Node 20.11+**.

## Размещение на сервере

```bash
npm run bundle     # dist/reels-widget-<дата>.tar.gz + snippet.html
```

Пошаговая инструкция, systemd-юнит, конфиг nginx и скрипт установки —
в [`deploy/README.md`](deploy/README.md). Коротко: сайт остаётся там, где
он сейчас, и получает одну строку в шаблоне, а сервис рендера едет на VPS.
На классический виртуальный хостинг он не встанет ни у какого провайдера:
нужен headless Chromium (~450 МБ, запуск процессов, рабочий `/dev/shm`)
и собственный бинарь ffmpeg.

## Встраивание

Один тег перед `</body>`:

```html
<script src="https://reels.example.ru/loader.js" data-reels-widget></script>
```

Появится круглая кнопка слева внизу. По клику открывается модальное окно
с виджетом, адрес текущей страницы подставляется сам, и разбор запускается
сразу — менеджеру остаётся выбрать сценарий. Посмотреть, как это выглядит
на чужой вёрстке: `/examples/host-page.html`.

| Атрибут | Что делает |
|---|---|
| `data-position` | `left` (по умолчанию) или `right` |
| `data-offset` | отступ от края, px |
| `data-accent` | цвет кнопки |
| `data-label` | подпись; на узких экранах скрывается |
| `data-page` | подставить другой адрес вместо текущего |
| `data-autoparse="false"` | не разбирать страницу сразу при открытии |
| `data-hide-on="/cart,/admin"` | пути, где кнопку показывать не надо |
| `data-api` | адрес сервера, если `loader.js` отдаётся с другого домена |
| `data-open-on-load` | открыть окно сразу (для отладки) |

Программно: `window.ReelsWidget.open() / .close() / .toggle()`, а для сайтов,
меняющих адрес без перезагрузки, — `.setPage('https://…')`.

Кнопка и окно живут в Shadow DOM, сам виджет — в iframe. Изоляция двойная
не из перестраховки: виджет попадает на сайты, где глобальное правило
`button { … }` из темы перекрашивает и ломает всё, до чего дотянется.

## Из чего состоит

| Пакет | Что внутри | Зависимости |
|---|---|---|
| `packages/core` | модель карточки, три адаптера, движок сценариев, свои парсеры XML и HTML | нет |
| `packages/stage` | сцена: `renderFrame` для превью и для захвата | нет |
| `packages/server` | HTTP API, очередь рендера, Playwright + ffmpeg | `playwright` |
| `packages/embed` | `loader.js` и интерфейс виджета | нет |

Единственная внешняя зависимость во всём проекте — Playwright. Парсеры XML и
HTML написаны свои: сервер принимает чужие файлы и ходит по чужим ссылкам,
и на этом пути меньше зависимостей значит меньше поверхности для обновлений
по безопасности.

### Как разбирается страница объекта

Три слоя, каждый следующий кладётся поверх предыдущего:

1. **Универсальный** — JSON-LD, OpenGraph, регулярки по тексту. Работает
   на любом сайте, но на сайтах застройщиков берёт мало: разметки
   Schema.org там обычно нет.
2. **Словарь характеристик** — пары «подпись — значение» из разметки.
   Сканер собирает их из таблиц, списков определений и соседних блоков,
   а словарь превращает «Площадь общая → 28.85» в поле карточки. Работает
   на любом сайте, где параметры размечены подписями.
3. **Профиль движка** — если страница узнана. Берёт максимум и без догадок.

Что именно получилось, показывает офлайн-инструмент — ни сети, ни сервера
он не требует:

```bash
npm run parse -- examples/fixtures/lot.html https://zhk-kosmos.alphasuper-baza.ru/flats/flat/1115
npm run parse -- page.html <url> --pairs   # все найденные пары и что распозналось
npm run parse -- page.html <url> --json    # карточка как JSON
```

Второй аргумент — адрес, с которого страница сохранена: по нему достраиваются
относительные ссылки на картинки и срабатывает определение профиля.

### Профили сайтов

Профиль — это объект в `packages/core/src/adapters/profiles.ts`: `detect`
отвечает «моя ли это страница», `extract` возвращает кусочек карточки,
`pageKind` различает страницу комплекса и страницу лота. Остальной конвейер
трогать не нужно.

В комплекте один профиль — **СуперБаза** (`zhk-*.alphasuper-baza.ru`).
Разметки Schema.org и OpenGraph на этих страницах нет вовсе, поэтому опора —
атрибуты `data-call-*` на кнопке звонка: готовая сводка с названием, адресом,
ценой, телефоном и главным изображением, одинаковая на обеих страницах.
Фотографии стройки отделяются по границам раздела «Ход строительства»
в документе, а подписи к ним берутся из `data-title` лайтбокса.

Чтобы добавить движок, сохраните страницу, напишите профиль и проверьте его
через `npm run parse` — цикл занимает минуты и не требует доступа к сайту.

### Сценарии

| Сценарий | Длина | Что показывает | Что обязательно |
|---|---|---|---|
| `complex-overview` | 10 с | название, локация, преимущества, цена «от» | название ЖК |
| `lot-plan` | 15 с | параметры квартиры, планировка, цена, платёж | название + площадь |
| `promo` | 10 с | оффер, было/стало, ставка и платёж, дедлайн | название ЖК |
| `progress` | 15 с | три кадра со стройки, готовность, срок сдачи | название ЖК |

Сценарий — чистая функция `Card → Timeline`. Добавить пятый — это один файл
в `packages/core/src/scenarios` плюс строка в реестре `SCENARIOS`.

Каждый сценарий на выходе проходит `assertTimeline`: ролик «на 10 секунд»
обязан быть ровно 300 кадров, сцены — идти без разрывов. Расхождение роняет
сборку, а не всплывает обрезанным финальным кадром после выгрузки.

### Вёрстка кадра

Подписи собираются потоковыми блоками (`stack`) с привязкой к нижнему краю.
Это не косметика: названия ЖК бывают и в два слова, и в семь, и при
фиксированных координатах длинное название наезжает на адрес. С привязкой
к низу блок растёт вверх, а нижняя граница остаётся на месте.

Весь значимый текст держится выше `y = 1440`: в Reels нижние ~420 px
перекрывают подпись, аватар и кнопки, а верхние ~280 px — шапка.

## API

Все ответы — JSON. `card` всегда проходит нормализацию заново на сервере,
даже если пришёл с клиента.

| Метод | Маршрут | Назначение |
|---|---|---|
| `POST` | `/api/extract/feed` | `{payload}` или `{url}` → список карточек |
| `POST` | `/api/extract/url` | `{url}` → карточка со страницы |
| `POST` | `/api/extract/manual` | поля формы → карточка |
| `POST` | `/api/timeline/available` | какие сценарии доступны этой карточке |
| `POST` | `/api/timeline` | `{card, scenario, theme?}` → таймлайн для превью |
| `POST` | `/api/render` | ставит рендер в очередь, отдаёт `job` |
| `GET` | `/api/jobs/:id` | статус и прогресс |
| `GET` | `/api/scenarios` | реестр сценариев |
| `GET` | `/health` | состояние и очередь |

Пример:

```bash
curl -s localhost:4000/api/extract/feed \
  -H 'content-type: application/json' \
  -d "{\"payload\": $(jq -Rs . < examples/feed.sample.xml)}" | jq '.cards[0].complex.name'
```

### Фирменные цвета

`POST /api/timeline` и `/api/render` принимают `theme`:

```json
{ "theme": { "accent": "#1F6FEB", "accentText": "#FFFFFF" } }
```

Переданный `accent` побеждает акцент сценария по умолчанию (у акции он
горячий, у обзора — тёплый, у стройки — синий). Поля темы проходят через
белый список: тема уходит прямо в inline-стили кадра.

## Настройки

Скопируйте `.env.example` в `.env`.

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `PORT` | `4000` | порт сервера |
| `PUBLIC_URL` | `http://localhost:PORT` | адрес в ссылках на готовые файлы |
| `ALLOWED_ORIGINS` | пусто | домены, которым можно дёргать API |
| `SCRAPE_ALLOWED_HOSTS` | пусто | домены, которые можно разбирать по ссылке |
| `SCRAPE_RESPECT_ROBOTS` | `true` | проверять `robots.txt` перед загрузкой |
| `SCRAPE_TRUSTED_HOSTS` | пусто | свои домены, для которых проверка пропускается |
| `SCRAPE_ALLOW_PRIVATE` | `false` | разрешить localhost — **только для локальной отладки** |
| `RENDER_CONCURRENCY` | `2` | параллельных рендеров |
| `RENDER_CRF` | `20` | качество H.264, меньше — лучше и тяжелее |
| `OUTPUT_DIR` | `.output` | куда складывать MP4 |
| `CHROMIUM_PATH` | — | свой бинарь Chromium вместо playwright-ского |

### Что обязательно закрыть перед продом

Два списка по умолчанию пустые, и сервер при старте об этом предупреждает:

* **`ALLOWED_ORIGINS`** — иначе API открыт любому домену.
* **`SCRAPE_ALLOWED_HOSTS`** — иначе `/api/extract/url` работает как анонимный
  загрузчик произвольных страниц. Обращения к `localhost` и приватным
  подсетям блокируются всегда, но это защита от SSRF, а не от злоупотребления.

Разбор чужих сайтов — отдельный разговор с юристами: `robots.txt`
проверяется, но согласие правообладателя на использование рендеров в роликах
код обеспечить не может.

**Про `robots.txt` и собственные сайты.** Сайты застройщиков часто закрыты
`Disallow: /` целиком — так ставят staging, и так остаётся после запуска.
Виджет такую ссылку честно отклонит. Правильный порядок действий: сначала
поправить `robots.txt` на своём домене; если это почему-то невозможно —
внести домен в `SCRAPE_TRUSTED_HOSTS`. Это именно список своих доменов,
а не глобальное отключение проверки: для чужих сайтов она продолжает
работать.

## Производительность

На одном ядре: 10-секундный ролик — около 25 с, 15-секундный — около 50 с.
Узкое место — скриншот каждого кадра, порядка 60–80 мс.

Если нужно быстрее:

* поднять `RENDER_CONCURRENCY` по числу ядер (каждый рендер держит вкладку
  Chromium, считайте ~400 МБ на вкладку);
* `RENDER_CRF=23` и `-preset ultrafast` в `packages/server/src/render.ts`;
* для потока в сотни роликов в час — вынести очередь из памяти процесса
  в BullMQ. Точка расширения в `packages/server/src/jobs.ts`: достаточно
  заменить `enqueue`/`getJob`, роуты трогать не нужно.

**Почему покадровая перемотка, а не запись экрана.** Запись зависит от того,
успел ли браузер отрисовать кадр вовремя, и на загруженном сервере даёт
рывки и плавающий хронометраж. Перемотка по номеру кадра идёт столько,
сколько идёт, а на выходе всегда честные 30 fps.

## Шрифты

Кадр набран Inter: полная кириллица, вариант Display для крупных заголовков.
Чтобы поставить свой шрифт, положите файлы в `packages/stage/fonts`, добавьте
`@font-face` в `stage.html` и поправьте `fontDisplay` / `fontBody`
в `packages/core/src/theme.ts`.

Шрифт обязан быть доступен и в превью, и при рендере — они грузят один и тот
же `stage.html`, так что подключать его надо именно там. Ссылка на внешний
CDN сделает рендер зависимым от сети: для прода шрифты лучше положить рядом.

## Известные ограничения

* Картинки грузятся по прямым ссылкам. Если хостинг застройщика закрывает
  хотлинк по `Referer`, кадр останется пустым — виджет показывает счётчик
  незагруженных изображений, чтобы это не всплыло уже в готовом файле.
* Звука нет: в MP4 пишется тихая дорожка, потому что часть площадок хуже
  обрабатывает видео совсем без аудио. Музыку накладывайте при публикации.
* Парсер страниц работает по разметке и тексту. Сайты, которые рисуют
  карточку целиком на клиенте, отдадут пустую страницу — для них используйте
  фид или форму.
* Очередь живёт в памяти процесса: при перезапуске незавершённые задачи
  теряются. Для одной ноды и отдела продаж это осознанный размен.
